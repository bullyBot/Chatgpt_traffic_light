# ChatGPT 任务红绿灯

一个 Chrome Manifest V3 扩展，用红绿灯显示已打开的 ChatGPT 页面状态，在需要你处理或确认完成时发送桌面通知。优先保证：**明确的待处理请求及时提醒，缺少完成证据时不发送完成通知。**

## 安装使用

需要 Chrome 120 或更新版本。

仓库内提供已构建的安装包：[chatgpt-traffic-light-v0.2.3.zip](releases/chatgpt-traffic-light-v0.2.3.zip)。在 GitHub 中打开该文件，点击「Download raw file」下载；也可以下载整个分支的 ZIP，解压后在 `releases/` 文件夹中找到它。更新源码后应重新构建安装包。

**v0.2.3 单灯样式**：工具栏与弹窗改用一个放大的圆灯，带玻璃反光和金属边框。绿色进行、黄色待处理、红色停止／完成／空闲，未识别时熄灭；状态检测、通知与黄灯保持逻辑不变。

**v0.2.2 等待输入识别**：新增带标题、可用输入项和提交按钮的问题卡片识别；支持最新、已知为助手的回复中明确的「请提供／请补充／请确认／请审阅」等请求。历史消息、代码、引用和条件式建议不作为文字请求。检测到待处理后保持黄灯，直到观察到用户回复、继续执行、取消、失败或新的明确任务结束标记；问答回复结束本身不等于整个任务完成。文字判断是有限规则，仍需要匹配该页面的回复结构，不能保证所有自然语言都能识别。

真实页面若未识别，可在该页面打开扩展，展开「连接诊断」，点击「生成当前页面控件诊断」。结果包含标签、CSS 类、静态界面标记、图标及控件附近的结构，可直接复制，不需要操作开发者工具；不包含聊天正文、输入内容、网址或元素 ID。它帮助校准实际 DOM，不会自动改变任务状态。

**v0.2.1 兼容性修复**：修正可点击的 Stop 子按钮被祖先 `pointer-events: none` 错误排除的问题；回复工具栏不再要求 `article` 外层，支持同一回复附近的赞/踩按钮和嵌套正文容器。支持明确的发送控件与可用输入区组合识别空闲，但本轮观察到执行后，只有输入区就绪仍不会发完成通知。赞/踩工具栏变化不会改变旧回复的完成指纹。诊断新增页面监听版本、停止控件的排除原因、正文/反馈配对和输入区数量，便于定位未识别原因。以上布局通过受控浏览器验证；用户的实际页面还需确认。

**v0.2.0 更新**：绿色表示执行中，红色表示停止、完成或空闲，黄色表示需要处理。未识别时三盏灯均不亮，只显示文字。移除普通文本「正在思考」的运行推断；忽略透明、不可点击或播放器内的停止控件。`/local/` 最新回复的赞/踩反馈可作为结束证据；已有完整回复时，无法明确归属任务执行的通用 Stop 按钮不覆盖空闲判断。明确的停止生成/中断控件仍优先表示正在执行。连接诊断增加结束证据、运行来源和停止控件资格，不复制正文或属性值。

**v0.1.1 修复**：新增 `/local/` 页面适配；安装、启动及打开弹窗时自动连接已打开的标签页；重新连接按钮可以补注入页面脚本；连接失败会显示原因。重复连接保留已有任务的观察基线。新增 `scripting` 权限用于连接 ChatGPT 页面。

1. 解压发布包 `chatgpt-traffic-light.zip`，得到含有 `manifest.json` 的文件夹。开发者也可以按下方步骤构建 `dist/`。
2. 在 Chrome 地址栏输入 `chrome://extensions`，打开右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择解压后的文件夹（或本仓库的 `dist/`）。
4. 将「ChatGPT 任务红绿灯」固定到工具栏，扩展会自动连接已打开的 ChatGPT 页面；也可以点击弹窗右上角「重新连接页面」。
5. 正常执行任务；点击扩展图标查看页面列表，点击任务或桌面通知返回任务。

Windows 系统设置中应允许 Chrome 发送通知。「勿扰」或「专注」设置可能隐藏桌面通知；工具栏仍会更新。

升级时，先移除旧扩展，再加载解压后的最新版文件夹，避免同时运行两个版本。若提示权限不足，在 Chrome 扩展管理页面的「详情 → 网站访问权限」中允许访问 ChatGPT。任务正在运行时，可以点击重新连接，不需要为建立连接而刷新任务页面。

弹窗显示「0 个页面」表示没有连接记录，并不表示任务空闲。若已有页面但状态仍为未知，展开「连接诊断」可查看页面类型和状态控件数量；诊断不含聊天正文、任务标题或任务编号。

| 灯色 | 含义 |
| --- | --- |
| 🟢 绿色 | 页面明确显示正在执行或生成 |
| 🟡 黄色 | 明确的批准、审阅或输入请求 |
| 🔴 红色 | 已停止、已确认完成或页面空闲；异常也亮红灯并显示原因 |
| 灯熄灭 | 未识别、断线、休眠或结束待确认；不能据此判断空闲 |

多个页面同时存在时，工具栏按「需要处理 → 正在进行 → 异常/未知 → 完成/空闲」显示。黄色数字表示需要处理的不同任务地址数；弹窗按页面列出。扩展不会自动批准操作或提交回答。

## 当前识别范围和限制

- 允许的网站：`https://chatgpt.com` 和 `https://chat.openai.com`。
- 常规聊天：根页面、`/c/<id>`、`/g/<id>`、`/g/<id>/c/<id>`。
- Work 本地任务页面：`/local/` 及其子路径。支持可见的 Stop、Interrupt、停止/中断控件，以及明确的任务状态标记；普通正文中的状态描述不作为判断依据。
- 预留的任务详情适配器：`/codex/tasks/<id>`、`/codex/task/<id>`、`/work/tasks/<id>`、`/work/task/<id>`。只有匹配明确状态控件才会识别；任务列表不汇总其中未打开的任务。
- 页面规则集中在 `src/detector.js`。它使用停止按钮、明确的审批弹窗/输入请求组件、任务状态标记和最新回复的赞/踩反馈控件。任务控件选择器是待真实界面校准的适配点，**不是官方 API，也不保证当前所有 Work 界面都具备这些标记**。
- 最新已知助手回复中的明确请求可触发黄色；任意问句、历史请求和条件式建议不能保证识别。无法可靠识别的页面灯熄灭，显示「未识别」。
- 仅监测已打开、可执行脚本的页面；关闭浏览器或标签页后不能继续监测云端任务。后台节流、休眠可能延迟提醒，超过 90 秒没有状态更新会显示未知（工具栏在下一次最多约 30 秒的检查时更新）。
- 刷新/切换会话会重新建立观察基线；如果只在完成后才打开页面，不发送完成通知。取消生成后也不发送完成通知。运行时按下 Escape 会保守地按取消处理，即使该次按键仅关闭了其他界面，也可能抑制本轮完成提醒。
- 当前自动验证使用受控页面，未访问用户已登录的 ChatGPT Work 页面。真实页面兼容性和 Windows 通知展示需按下方步骤验收。

## 防误报规则

1. 黄色来源为可见状态控件、可操作的审批/输入组件，或最新已知助手回复中的明确请求。忽略隐藏节点、旧消息、代码和引用中的示例。
2. 先观察到运行或待处理，才能进入本轮完成确认。
3. 常规聊天及 `/local/` 需要看到最新回复的结束控件，且回复指纹与本轮开始时不同；任务详情需要明确的完成状态。
4. 完成证据至少稳定 2.5 秒，并在后续扫描中再次出现；控件消失、长时间无变化、失败和取消都不等于完成。
5. 同一状态转移只通知一次；相同地址的多个标签页在 30 秒内出现相同提醒时做跨标签去重。通知关闭期间不会积压旧提醒。
6. 状态先保存到 `chrome.storage.session`，再发送通知，使后台 service worker 重启不会重放已经处理的状态转移。

## 本地开发

Node.js 22+，npm。扩展运行时没有第三方依赖。

```sh
npm ci
npm test
npm run build
```

将 `dist/` 加载到 Chrome。修改后重新运行构建，在扩展管理页面点击重新加载，再刷新 ChatGPT 页面。

```sh
# 使用已安装的 Chromium 运行真实扩展集成测试
CHROMIUM_PATH=/path/to/chromium npm run test:browser

# 真实 Chromium 页面与弹窗测试，Chrome 扩展 API 使用测试替身
npm run test:ui

# 打包可加载的扩展，使用 Python 3 标准库
npm run package
```

Linux 测试默认 Chromium 路径为 `/usr/bin/chromium`。`test:browser` 通过现代 Chromium 的 DevTools 扩展加载接口加载真实 MV3 扩展，需要支持 `Extensions.loadUnpacked` 的新版本 Chromium，且管理策略允许加载未打包扩展。该命令在当前云机器上被管理员策略阻止，尚未通过。

`test:ui` 在真实 Chromium 中运行构建后的页面监听、后台逻辑和弹窗，用内存中的 Chrome API 测试替身连接这些组件；它可在禁止安装扩展的环境中验证 DOM、计时、取消操作、状态汇总、通知参数和设置逻辑，但不能证明实际 MV3 加载成功。

两类浏览器测试均拦截测试域名请求并返回本地模拟页面，不需要 ChatGPT 账号；桌面通知调用被捕获，不代表 Windows 通知实测。截图保存到 `artifacts/popup.png`，扩展包保存到 `artifacts/chatgpt-traffic-light.zip`。

## 手工验收

| 场景 | 预期 |
| --- | --- |
| 首次打开已有完整回复的对话 | 可显示空闲；不弹完成通知 |
| 新任务开始 | 绿灯 |
| 当前页面出现受支持的明确审批或输入请求 | 黄灯；活动页面目标 2 秒内提醒；重复渲染不重复弹出 |
| 处理请求后继续执行 | 绿灯；下一次新的待处理请求可以再次提醒 |
| 回复结束并出现受支持的结束控件 | 确认后变红，只通知一次；正常前台扫描约需 3–5 秒 |
| 点击停止生成 | 红灯，显示已停止；不弹完成通知 |
| 网络中断、隐藏完成控件、执行控件突然消失 | 未知，不推断完成 |
| 一个任务运行、另一个等待审批 | 工具栏黄灯，列表分别显示两个状态 |
| 关闭一个页面 | 从列表移除 |
| 点击通知或列表任务 | 激活对应标签页和窗口 |
| 关闭桌面通知开关 | 灯色照常更新，不发送新通知 |
| 真实 Work 页面始终未识别 | 在 `src/detector.js` 校准该页面的状态控件；不能据此宣称任务已完成 |

## 文件结构

```text
src/detector.js       网站状态识别与可见性判断
src/connection.js     页面探测、按需注入、连接失败原因
src/model.js          任务状态转移、完成确认、防重复提醒
src/content.js        页面监听、取消捕获、状态心跳
src/background.js     状态存储、工具栏、通知和标签页生命周期
src/popup.*           任务列表、灯色说明、通知开关
tests/                状态与 DOM 识别测试
scripts/              构建、浏览器集成验证、打包
```

## 隐私和权限

没有服务器、统计追踪或外部状态上传。内容脚本在本地读取页面状态，以及最新回复的文字来计算变化指纹；不会保存回复正文。当前会话状态包含页面标题、不含查询参数的任务地址、状态、时间和指纹，保存在浏览器会话存储中；通知开关保存在本地存储中。页面标题会用于本机桌面通知，因此可能出现在通知中心。

网站访问范围仅限两个 ChatGPT 域名；`storage` 用于状态和设置，`notifications` 用于提醒，`alarms` 用于检查过期状态，`scripting` 用于在已打开的 ChatGPT 标签页中按需注入状态监听脚本。无需账号密码、API key 或读取其他网站的权限。
